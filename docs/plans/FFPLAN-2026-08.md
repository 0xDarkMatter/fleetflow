# Design plan: `ff-plan` — spec → launch-ready fleet runs, up to whole applications

**Status:** draft (2026-08-20, not yet reviewed) · This is a *design* plan for a
new skill surface, not a run plan; once approved, its load-bearing decisions
land as ADRs **before** any packet is authored (docs contract: plans cite,
ADRs own). Sections marked **[→ADR]** are labelled hypotheses awaiting that
promotion. The build itself is a fleet run — see §12.

---

## 1. Mission

fleetflow's lifecycle starts at `ff-doctor`; everything before it — reading the
spec, decomposing into file-disjoint packets, routing models, pasting ADR
constraints, writing the plan doc — is manual orchestrator craft. `ff-plan`
puts a structured, lintable, refutable planning stage in front:

```
ff-plan draft → ff-plan lint → ff-plan refute → ff-doctor → ff-spawn … → land
```

Scale target: from a single-feature run (today's RUNCARD/WAVES shape) up to
**entire applications** — greenfield seeding, architecture selection,
contract freezing, multi-phase build DAGs, generator-backed sub-fleets
(Forma), post-build waves, and landing. Judgment stays in the orchestrator;
`ff-plan` owns the deterministic mechanics and the gates.

## 3. Design principles **[→ADR, one each]**

1. **`ff-plan` authors the manifest; the lint gates the spawn.** Today the
   manifest accretes as a spawn side-effect; under ff-plan it is written
   up-front (packets, phases, deps, routing) and `ff-spawn` consumes it.
   Unchanged runtime — the journal, cache keys, and resume semantics
   (ADR-012) are untouched.
2. **Pipeline-first decomposition.** The plan is a dependency DAG, not
   lockstep waves. A barrier appears only where a stage genuinely consumes
   *all* prior results (integrated-tree refute, dedup, land), and the plan
   must name what each barrier joins. Each build lane flows to its own
   verifier independently.
3. **The plan is the first artifact through the adversarial pipeline.**
   Cross-provider refutation of the decomposition before any build token is
   spent. fleetflow refutes docs and code; the plan was the only exempt
   artifact.
4. **Generator-backed work classes.** During decomposition each candidate
   packet is asked "does a factory exist for this shape?" If yes, it becomes
   *invoke-generator + customise + verify-with-the-generator's-own-gate*,
   routed cheap. Forma is the first registry entry (§8).
5. **Lints report armed/disarmed, not just pass/fail.** Every gate says
   whether it actually ran (fleet-ops postmortem 2026-07-28: a silently
   disarmed test gate ran green for weeks).

## 4. CLI surface

`scripts/ff-plan.sh` — bash, Skill Resource Protocol, same exit-code family
as siblings (`0` ok, `2` usage, `3` missing, `10` findings).

| Subcommand | Does | Writes |
|---|---|---|
| `draft --run NAME --spec FILE [--shape SHAPE]` | scaffolds `docs/plans/<RUN>.md` from the template + one packet stub per lane row + the manifest skeleton (`phases[]`, `packets[]` with deps/model/locus). `--shape` picks an archetype (feature, review, research, migrate, **app** — §10). Decomposition content is orchestrator judgment guided by the SKILL.md checklist (§5); draft emits structure, never invents scope. | plan doc, packet stubs, manifest |
| `expand --run NAME --generator forma --vars FILE` | mechanically expands a generator request into its known sub-fleet (§8): packets, deps, mutex lanes, human-gate checkpoints | packets + manifest entries |
| `lint --run NAME` | the mechanical gate (§6); exit 10 on findings; `--json` for the orchestrator | report only |
| `refute --run NAME [--model codex\|grok\|glm\|pi]` | spawns one cross-provider lane prompted to attack the decomposition (§9); findings append to the run ledger like any wave | ledger entries |
| `estimate --run NAME` | per-lane and total cost/wall-clock via `loop-estimate` + `model-pricing.json`; declares any coverage bounds (no-silent-caps) | report only |

`ff-run resume` and `ff-status` read the same manifest they always did.

## 5. Packet anatomy

One file per packet at `.fleetflow/<run>/packets/<id>.task.md` (unchanged,
ADR-012 cache-key purity: no timestamps, no randomness). New: YAML
frontmatter, the machine-readable half:

```yaml
---
id: build-auth                     # matches filename stem
class: build                       # mechanical|scout|build|verify|judge|generator|interactive
model: glm                         # spawn alias; judges: omit-to-inherit rule applies
locus: process                     # process|in-proc (fleet-worker locus rule)
owns:                              # exclusive-write; overlap with another packet's owns/modifies = finding
  - src/auth/**
modifies: []                       # shared-edit; overlap = finding (weaker severity)
reads: []                          # informational
registries: []                     # shared registries touched (pyproject, tests/run.sh, pricing tables) — single-writer enforced
depends_on: []                     # packet ids; edges, not waves
generator: null                    # e.g. forma — marks a stamped packet (§8)
gate: auto                         # auto|review|stop (ADR-018 vocabulary)
final_reply:                       # declared shape, validated at collect
  - "TESTS: <passed>/<failed>"
  - "FILES_CHANGED: <n>"
---
```

### 5b. Role cards (`assets/roles/*.role.md`) **[→ADR]**

fleetflow has role *vocabulary* (refuter, judge, orchestrator) but no role
*definitions* — every run re-improvises the refuter's attack stance from
SKILL.md prose. Axiom defined roles well (lane files: mandate,
owns/never-touches, hard rules); the native Workflow tool splits role into a
**persistent contract** (agent-type definitions: system prompt + tool bounds +
model) and an **ephemeral stance** (prompt patterns, each paired with a
structural rule — refuters default-refute on uncertainty, judges score stated
criteria only, finders dedup vs *seen*). Role cards merge the two: Axiom's
form, native's content. Each card: mandate (2–4 lines) · stance rules (the
structural doctrine, verbatim from the quality patterns) · capability bounds
(read-only? self-commit? tool notes) · output contract (FINAL REPLY shape
default) · anti-patterns.

**Naming convention: one-word trade-guild personas, Forma's register**
(Architect / Scout / Inspector / Verifier / Warden) — a seat is named for
what it *is*, not its stance adjective; where a meaning coincides with a
Forma role, the same word is used verbatim so generator packets read natively
in fleet plans. Card files kebab-case: `assets/roles/<persona>.role.md`.

Initial roster: **Architect** (N independent sketches,
options-with-tradeoffs, never code) · **Oracle** (spec/domain authority;
read-only Q&A, every answer cited to the spec) · **Scout** (internal
inventory, cite file:line, never modify) · **Surveyor** (one search modality,
blind to sibling Surveyors) · **Scholar** (close-reads what Surveyors found)
· **Builder** (exclusive scope, contracts verbatim, progressive commits,
report-don't-improvise) · **Inspector** (install/run/test — Forma's meaning,
adopted verbatim) · **Skeptic** (attack never confirm; default-refute on
uncertainty; concrete failure scenario per claim; lens-parameterisable) ·
**Judge** (stated criteria only; never under-powered;
synthesize-from-winner) · **Critic** (completeness: what's missing becomes
the next round) · **Synthesist** (post-barrier consolidation; premium seat) ·
**Warden** (sole writer of shared registries and joins — the mutex lane;
Forma's meaning, adopted verbatim). Wave-packet templates stay as-is — they
are finder role cards that predate the naming.

"Researcher" is deliberately **not** a role: the native Research archetype
decomposes it into sweep → deep-read → synthesize → critic. `ff-plan draft
--shape research` expands it as a pipeline, the way `expand` treats Forma.

Packets gain `role:` in frontmatter; `draft` prepends the card to the packet
body; lint checks role ↔ class coherence (a Skeptic on a `mechanical` class
= finding; Judge/Synthesist seats must never be down-routed).

Body sections (from the Axiom template + fleet-ops brief, modernised):
**Context** → **Scope (exclusive)** with per-path justification → **Read
first** (ordered, with line ranges) → **Constraints from standing decisions**
(pasted ADR BLUFs — lint-enforced) → **Contracts (frozen, verbatim)** →
**Steps** → **Tests** (tee'd command + exit capture) → **Done criteria** →
**If you get stuck** (report-and-stop rules). Self-contained for a cold
worker; 800–1500-word guidance (soft).

## 6. The lint catalogue

All findings exit 10; each check reports `armed` or `disarmed(reason)`.

| # | Check | Source |
|---|---|---|
| a | **Scope conflicts** — pairwise owns/modifies matrix (Axiom's table: owns×owns hard, owns×modifies / modifies×modifies warn; globs; trailing `/` = `dir/**`); plus `registries:` single-writer | Axiom scope.py |
| b | **Dependency edges** — no packet's deliverable appears in another's inputs without a declared dep; DAG has no cycles/orphans; bottleneck report (≥3 dependents = critical path) | subagent-orchestration + Axiom |
| c | **ADR constraints** — `adr-touching` per packet's owns/modifies; a governing ADR whose BLUF is absent from the constraints block = finding; stale `touches:` in the repo's ADRs = warning | adr-ops |
| d | **Packet contract** — frontmatter schema valid; FINAL REPLY declared; tests command present for file-mutating packets; self-containment heuristics (no "as discussed", no absolute machine paths); contracts sections byte-identical where two packets cite the same contract | Axiom parcel-generate |
| e | **Routing sanity** — every packet has class+model+locus; judge packets not under-powered (omit-to-inherit, never pin down); effort-lever-first noted; serial steps marked `interactive` and excluded from spawn | fleet-worker routing |
| f | **Barrier justification** — any phase boundary that is a true barrier must name what it joins; unjustified barriers = finding | native §3 |
| g | **Bounds declared** — estimate ran; any top-N/sampling/skip is stated in the plan doc | native no-silent-caps |

## 7. Plan-doc template (`assets/plan.tmpl.md`)

Freeze the converged RUNCARD/WAVES/SWEEPFAST format and add the Axiom
planning-lane mandates:

- Status header, cite-never-restate, binding rules block.
- Machine header: `GOAL / SPEC / PHASES / PACKETS / CRITICAL-PATH /
  EST (assuming K-parallel) / DETECTED-CONFLICTS / BOUNDS`.
- §-numbered shared contracts.
- Lane table: `id | class | model | owns (exclusive) | builds | gate`.
- **Dependency sketch** (ASCII DAG) with prose for *why* each edge exists.
- **Degradation plan** — "if something slips, drop X first".
- **Risk register** — ≥5 risks, likelihood × impact × mitigation (app-shape
  plans; optional for feature-shape).
- **Verify plan** — refuter seats, judge seats, providers named.
- **Chip seats** — human-attended lanes, if any; these are the lanes session
  messaging can steer (desktop-orchestrator convenience, never load-bearing).

## 8. Generator-backed packets: Forma first

`references/generator-registry.md` maps request shapes → expansions.
Entry 1, **Forma** (`ff-plan expand --generator forma`), from 12 Architect
variables + API-docs URL:

```
scout(opt) → architect ──> verifier ─┐
                        └> inspector ─┴> mcp-design → [HUMAN GATE] → mcp-build → warden
```

- One lane per tool directory (Forma's own contention table guarantees
  disjointness); **warden is a global mutex lane** — sole writer of
  `registry.json`, `registries:` enforced by lint (a); multiple tools fan out
  in parallel and share one warden lane.
- Routing: architect + mcp-design premium; verifier/inspector cheap
  (checklist grind); mcp-build mid, against the approved manifest only.
- The Coverage Map (every endpoint → command, 100%) is the one unbounded
  sub-task; large APIs split by resource group into sibling packets.
- Acceptance = the generator's own gates: verifier verdict ≥ MINIMUM_VIABLE,
  inspector green, §30 13-box MCP checklist. `forma log query` reconciles
  stage completion against the manifest.
- **Frictions, resolved in the expansion, not per run:** (1) Forma's headless
  prompts say `bypassPermissions` — ff-plan packets keep fleetflow's gated
  sandbox model (loop-engineering: bypass only in isolated containers);
  (2) prompts hardcode `/Users/mack/projects/Forma` — expansion injects the
  real ecosystem root; (3) Forma repos forbid `Co-Authored-By` — expansion
  sets the trailer policy per packet.

## 9. Plan refutation

One cheap cross-provider lane (default: whichever provider has no build seat
in the run), prompted to attack, not confirm:

- hidden coupling: two packets that will both need a file neither declares;
- shared-registry writers not serialised;
- contracts referenced but not frozen verbatim;
- a barrier that joins nothing / a missing barrier before an integration lane;
- verify seats under-powered or same-provider as the builder they check;
- spec requirements no packet owns (completeness critic).

Findings enter the ledger (`ff-findings`) with wave `plan`; triage/fix uses
the existing ADR-018 machinery. Two refute rounds max, then escalate —
mirroring the fix-loop rule.

## 10. The `app` shape — whole applications

The archetype for greenfield/complex builds; phases are manifest entries,
gates use ADR-018 vocabulary (`--attend`, per-phase `gate`).

| Phase | Content | Barrier? |
|---|---|---|
| 0 seed | repo scaffold, `adr-init`, spec ingested into the repo (`spec/`, relative paths — SKILL.md rule), ADR-001..N for the load-bearing choices | interactive |
| 1 architecture | judge panel: N independent architecture sketches from different angles (different providers), judges score, orchestrator synthesizes; output = ADRs + module map | barrier (joins: all sketches) |
| 2 contracts | freeze module boundaries + interfaces as §-contracts in the plan doc; every later packet cites, never restates | review gate |
| 3 build | file-disjoint build DAG per module; generator packets (Forma etc.) expand here; each lane flows to its own cross-provider refuter as it finishes | no barrier |
| 4 integrate | one integration lane per declared join; shared registries (deps files, manifests) single-writer here — build lanes *note* needed deps in FINAL REPLY instead of editing (Axiom §17) | barrier per join |
| 5 waves | `ff-run wave` with posture per risk (`hardened` default for apps) | ADR-018 |
| 6 land | fleet-ops queue; deploy stays maintainer-gated (ADR-018 non-goal) | stop |

Scale levers: budget-scaled lane count; packet count bounded by integration
capacity, not a fixed number — the plan must state its bound (lint g).

## 11. Non-goals (deliberate)

- No queue/daemon — spawn/journal/collect is the runtime (Axiom retired its
  own; "what NOT to build": no agent-to-agent messaging, no rollback
  framework, no persistent agent state).
- No auto-decomposition — `draft` scaffolds; scope judgment is never
  generated by the tool itself. The refuter checks the human/orchestrator,
  not the other way round.
- No new telemetry channel — raven (ADR-022/023) and `forma log` (for
  generator packets) cover it.
- Session messaging steers **chips only**, never workers; desktop-only
  convenience, degrade silently headless.

## 13. Open questions (resolve before ADRs land)

1. Frontmatter on packets changes the spawn cache key for any *re-authored*
   legacy packet — acceptable (they re-run once), or strip frontmatter before
   hashing? Leaning: hash the whole file, accept the one-time miss (ADR-012
   purity beats cleverness).
2. Does `lint` also run inside `ff-doctor --offline` so a fleet can't be
   blessed with a conflicted plan? Leaning: yes, as a doctor section.
3. `registries:` single-writer — enforce as hard (like owns×owns) or warn?
   Axiom's incident history says hard.
4. Refuter default provider: "no build seat in this run" needs a fallback
   when all providers build. Leaning: pi wildcard.
5. Should `expand` live per-generator in the registry doc as prompt templates
   only (no code), keeping ff-plan.sh generator-agnostic? Leaning: yes —
   registry doc owns the expansion tables, script stays generic.
